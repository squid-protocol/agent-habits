# Does more time make different code? (EXPLORATORY follow-up, not preregistered)

1. **Haiku is slow because each attempt is long, not because it fails more.** Median per run: Haiku ran the checker 3 times (2 self-checks + the harness check), Sonnet 2, Codex 6; but Haiku spent ~280-540 s per checker run vs Sonnet's 62-72 s and Codex's 90 s. Haiku made ~38-42 tool calls per run vs Sonnet's 2 (Sonnet writes the program in one go), at a similar ~30-40 s per call. Haiku was never nudged (Codex: 5 of 12 runs).
2. **Across models, time and size do not track each other.** Same cell, same round: Haiku took 6.3x as long as Sonnet (median of 20 cell ratios; 20 of 20 longer) and wrote 1.8x the code lines (19 of 20), 1.9x the functions and 6.2x the comment lines. But Codex took 4.2x as long as Sonnet and wrote *less*: 0.42x the lines, 0.55x the bytes (bigger in 2 of 20). Haiku took only 1.3x Codex's time but wrote 5.4x its lines (3.4x its bytes).
3. **Within a model, the slower run is not the bigger one: a coin flip.** Same model, same task + language (S vs S2, K vs K2, Codex r1 vs r2; 22 pairs): the slower run had more code lines in 13 of 22 (p = 0.52) and more bytes in 11 of 22. By model: Sonnet 8 of 10, Haiku 4 of 10, Codex 1 of 2. Spearman time vs code lines: rho = 0.40 over all 60 runs (0.56 after removing cell size), but within a model, against its own cell median, Sonnet rho = 0.34 (p = 0.10) and Haiku -0.23 (p = 0.28). The two rise together only because Haiku is both slow and verbose.

Caveats: exploratory, decided after the results; small n (10 cells, 22 within-model pairs, 12-24 runs per correlation) and many comparisons, so p values are descriptive.
One lead, not a finding: within Haiku, longer runs had more comment lines (rho = 0.43, p = 0.035; slower run more comments in 7 of 10 pairs); Sonnet shows none (-0.16).
Lines are counted directly from the source (non-blank, non-comment-only, cell language); Codex packs statements per line, so bytes are given too. Functions are ctags counts (GitGalaxy could not read 4 dense Codex runs).
"Checker runs" = the agent's own `/check/check` calls in its transcript plus one harness check per session; times are active seconds. The one capped Haiku run is in the pairs; dropping failed/capped pairs: 13 of 21.
